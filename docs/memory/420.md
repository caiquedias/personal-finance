## Decisões técnicas
- Colunas definidas pelas faixas de X do cabeçalho de cada página; página sem cabeçalho reaproveita o da anterior. Linhas agrupadas por Y com tolerância de 3pt.
- Período ("dd/MM/yyyy a dd/MM/yyyy") interno ao parser, sem DTO wrapper; resolve virada dez→jan.
- Cultura `pt-BR` explícita (não depende da thread).
- `DomainException` para senha ausente/errada (`PdfDocumentEncryptedException`), stream inválido, falha ao ler páginas e linha de lançamento inválida (`dd/MM` válido nas duas colunas de data com data/valor inválido). Mensagens sem descrição/valor. `OperationCanceledException` nunca é convertida.
- Linhas cuja 1ª/2ª coluna não é `dd/MM` (Saldo do dia, continuação de descrição, cabeçalhos) são descartadas. PDF sem linhas → lista vazia.
- Stream não seekable é copiado para `MemoryStream` antes de abrir.

## Desvios do spec
- Nome do pacote NuGet é `PdfPig` (o id `UglyToad.PdfPig` não tem a 0.1.9 estável); o namespace segue `UglyToad.PdfPig`.
- Ciclo de correção pedido pelo Caique após review aprovado com apontamentos (commits 7ef6d7b, 8b15994).
- Sem teste automatizado para a conversão de falha na leitura lazy de páginas (PdfPig tolera PDF corrompido; não foi possível sintetizar).
- Falha pré-existente, fora do escopo: `ExcelParserServiceTests.Parse_PrimaryIncome_ShouldExtractFromB4Formula` (também falha em develop).

## Débitos (Reviewer, baixa severidade)
- Validar contra extrato real anonimizado quando o use case de #418 consumir o parser (rodapé com duas datas `dd/MM` e sem valor válido lançaria exceção).

- `MemoryStream` da cópia não é descartado explicitamente (inócuo); `ParseAsync` é síncrono (CPU-bound).
