## Decisões técnicas
- Workflow novo e separado: `ci.yml` só roda em master e o `sync-branches.yml` (`workflow_run`) não filtra branch/evento — incluir o scan ali dispararia sync/deploy em PR.
- npm audit só de produção (`--omit=dev`): `braces` (GHSA-vfj7-8cjw-p6xm, high, ReDoS) não tem versão corrigida upstream e entra só pelo Karma (dev). Débito aceito pelo Caique; resolução futura: migrar Karma/Jasmine → Vitest (~933 specs, sizing L). Issue não aberta.
- `npm audit` sugeriu `karma@4.0.0` e `@angular/cli@20.0.6`: são downgrades (artefato do audit), ignorados.
- Gate NuGet cobre só High/Critical; é fail-open se o feed de vulnerabilidades estiver fora (débito registrado).

  - Escopo: upgrades de baseline não previstos no planning (XS → M)
- **Melhorias propostas (aplicadas em docs/testing.md, docs/patterns.md e docs/sprint-planning.md):**
  - Validar mudanças de `package-lock.json` com `npm ci` em container Linux (`node:20`) antes do push
  - Em migrações de stack CSS/build, validar o CSS compilado (não só build/testes) no QA
  - Rodar `npm audit`/`dotnet list --vulnerable` no Sprint Planning de issues de segurança para dimensionar o baseline
