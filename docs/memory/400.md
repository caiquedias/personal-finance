# #400 — [Security] Escopar authInterceptor à API própria
Issue: #400 | Data: 2026-10-05 | Branch: feat/400-escopar-authinterceptor-a-api-propria

## Arquivos criados
- `personal-finance/src/app/core/auth/vercel-csp.spec.ts` — valida os headers de segurança do `vercel.json` (CSP, nosniff, Referrer-Policy)

## Arquivos modificados
- `personal-finance/src/app/core/auth/auth.interceptor.ts` — Bearer e logout em 401 só para URLs da API própria (`url === apiUrl || url.startsWith(apiUrl + '/')`); demais requests passam direto
- `personal-finance/src/app/core/auth/auth.interceptor.spec.ts` — 5 specs migrados para `${environment.apiUrl}/...` + 7 novos (externa, relativa, prefixo sem fronteira, `.evil.com`, 401 externo/relativo)
- `personal-finance/vercel.json` — `headers` com CSP bloqueante, `X-Content-Type-Options: nosniff`, `Referrer-Policy`
- `personal-finance/angular.json` — produção: `optimization.styles.inlineCritical=false` (o critical CSS gerava `onload` inline, bloqueado por `script-src 'self'`)

## Decisões técnicas
- Checagem com fronteira (`apiUrl` ou `apiUrl + '/'`) em vez de `startsWith` simples — evita `apiUrlx` / `apiUrl.evil.com`
- 401 de fora da API não chama `logout()` (decisão do Caique)
- CSP no SPA (Vercel), não na API (só devolve JSON) — opção B escolhida pelo Caique; `style-src 'unsafe-inline'` necessário (Angular Animations/ngx-echarts); `script-src 'self'` estrito

## Desvios do spec
- Issue previa "avaliar CSP no backend": implementada no SPA (`vercel.json`) por decisão do Caique; backend sem alteração
- Adicionado `inlineCritical=false` em `angular.json` (fora dos arquivos listados na issue, necessário para a CSP)
- Débito: CSP não validada em navegador real com a política ativa; host do Render duplicado em `connect-src` e `environment.prod.ts`; faltam HSTS e Permissions-Policy no front
