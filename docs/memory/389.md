# #389 — [Security] Remover JWT SecretKey hardcoded e rotacionar
Issue: #389 | Data: 2026-07-04 | Branch: feat/389-remover-jwt-secretkey-hardcoded

## Arquivos criados
- `tests/PersonalFinance.Api.Tests/Integration/Security/AppSettingsJwtSecretKeyTests.cs` — teste de regressão: lê `appsettings.json` bruto do disco e assere `JwtSettings.SecretKey == ""`

## Arquivos modificados
- `src/PersonalFinance.Api/appsettings.json` — `JwtSettings.SecretKey` de hardcoded para `""` (mesmo padrão de `appsettings.Production.json`)
- `tests/PersonalFinance.Api.Tests/Integration/TestWebApplicationFactory.cs` — construtor estático injeta secret de teste fixo via env var `JwtSettings__SecretKey`, independente do valor em `appsettings.json`
- `README.md` — nova seção "Configuração de ambiente": setup via User Secrets (dev local), env var `JwtSettings__SecretKey` no Render (homolog/prod), nota sobre rotação invalidar sessões ativas

## Decisões técnicas
- `TestWebApplicationFactory`: a abordagem original planejada (`ConfigureAppConfiguration` + `AddInMemoryCollection`) não funcionou — `Program.cs` (minimal hosting) lê `builder.Configuration.GetSection("JwtSettings")` de forma síncrona antes de qualquer callback de `ConfigureWebHost` rodar. Resolvido com `Environment.SetEnvironmentVariable("JwtSettings__SecretKey", ...)` em construtor estático da factory — env vars têm precedência garantida sobre `appsettings.json` na ordem de fontes de configuração do `WebApplicationBuilder`.
- `ci.yml` não foi alterado — decisão validada com o Caique. O workflow só roda `dotnet test` (sem env vars de runtime da API) e dispara webhooks de deploy (Render/Vercel); a suíte de testes não depende mais de nenhum secret externo.

## Desvios do spec
- Task 4 do planning original (mapear `JWT_SECRET_KEY` como GitHub Secret no `ci.yml`) foi descartada — ficou obsoleta assim que a `TestWebApplicationFactory` passou a se auto-suficientar com um secret de teste fixo.
- Rotação do secret real em produção é ação operacional (painel Render), fora do escopo de código desta issue — registrada como pendência no PR.

## Follow-ups sugeridos pelo Reviewer (não bloqueantes)
- Secret antigo hardcoded permanece em texto puro no histórico do Git anterior a esta branch — deve ser tratado como comprometido e nunca reaproveitado.
- `Program.cs:24-25` só falha rápido (fail-fast) se `SecretKey` for `null`, não se for string vazia — recomenda-se trocar guard para `string.IsNullOrWhiteSpace(...)` em issue futura.
