## Arquivos modificados

## Decisões técnicas
- ForwardedHeaders no código (opção a, aprovada pelo Caique): XForwardedFor | XForwardedProto, `KnownNetworks`/`KnownProxies` limpos (IP do proxy do Render é dinâmico); `UseForwardedHeaders` é o primeiro middleware. Sem isso `Request.IsHttps` é sempre false no Render e o HSTS nunca é emitido
- Ordem: UseForwardedHeaders → ExceptionMiddleware → UseHsts (não-Dev) → UseHttpsRedirection → Swagger (Dev) → CORS → Auth → MapControllers
- HSTS sem Preload/IncludeSubDomains (onrender.com é domínio compartilhado)
- Testes: factory via `WithWebHostBuilder` + `UseEnvironment("Production")`, `AllowAutoRedirect=false`; caso (a) envia `Host: api.example.com` porque `HstsOptions.ExcludedHosts` exclui localhost por padrão

## Desvios do spec
- Issue pedia só `UseHttpsRedirection` + `UseHsts`; `UseForwardedHeaders` foi adicionado com aval do Caique (mesmo arquivo)

## Débitos (Reviewer, baixa severidade, não registrados em docs/sprint-planning.md)
- Proxies limpos permitem spoofing de `X-Forwarded-*` por cliente que acesse o container direto (risco aceito: Render é o único ingress)
- Sem `HttpsRedirection:HttpsPort` em produção o redirect não é exercido (só loga warning); inofensivo, HSTS vem via forwarded headers
- `using Microsoft.AspNetCore.HttpOverrides;` fora da ordem alfabética em Program.cs
